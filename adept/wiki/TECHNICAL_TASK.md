#Распределённая Key-Value БД для хранения кэша*
Redis — хороший пример Key-Value хранилища, однако реализация собственной БД с поддержкой распределённого хранения данных позволит глубже разобраться в устройстве систем хранения и распределённых систем.

**Задача**
Необходимо реализовать собственную Key-Value БД, предоставляющую следующие возможности:

1. **Базовые операции с данными:**
* `SET` — установка значения;
* `GET` — получение значения;
* `SET NX` — установка значения только в случае отсутствия ключа;
* `DEL` — удаление ключа.


2. **Работа с TTL:**
* установка времени жизни ключа;
* получение оставшегося TTL;
* автоматическое удаление просроченных ключей.


3. **Поиск ключей:**
* получение списка ключей;
* фильтрация ключей с использованием регулярных выражений.


4. **Транзакции:**
* возможность выполнить несколько операций атомарно;
* например, удалить набор существующих ключей и установить вместо них новый список значений.


5. **Атомарное изменение данных:**
* возможность выполнять произвольную логику изменения ключей с использованием Lua-скриптов;
* выполнение скрипта должно быть атомарным относительно других операций.


6. **Распределённый режим:**
* возможность запускать несколько экземпляров БД;
* распределение данных между узлами;
* маршрутизация запросов к узлу, на котором находятся необходимые данные;
* обработка отказа отдельных узлов и восстановление их состояния.



При реализации необходимо самостоятельно продумать формат хранения данных, протокол взаимодействия клиента с сервером и механизм распределения данных между узлами.
